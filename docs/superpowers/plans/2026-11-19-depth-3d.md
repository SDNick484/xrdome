# Depth-based 3D: implementation plan

Spec: `docs/superpowers/specs/2026-11-19-depth-3d-design.md` (section numbers below are the spec's). Each task is
one PR against `main` and one prompt issue. Gate for every task (CLAUDE.md): `meson setup build -Dwerror=true &&
meson compile -C build && meson test -C build --print-errorlogs` and `python3 -m pytest tools/tests -q`.

Shape: Tasks 2 (Python) and 3 (C) both need only Task 1 and run side by side; Task 4 builds on 3; Task 5 joins 2
and 4. Photo mode is usable after Task 4 with `depth photo` run by hand, and complete after Task 5.

```
1 setup depth + docs -> 2 depth photo (helper) ------------.
                     -> 3 images in 2D -> 4 depth 3D shader -> 5 helper service -> 7 video frames -> 8 video depth
                                                                                -> 6 polish (owner picks)       -> 9 glasses run
```

## Task 1. Spec, plan, `setup depth`, models registry (spec 4)

- Add this plan and the spec.
- `tools/xrdome_tools/setup.py`: a `depth` variant beside `to3d` (`setup depth [--cpu] [--yes] [--dry-run]`):
  depth venv, temporary export venv, export, sha256 check of the six model files, delete the export venv, write
  `depth/xrdome-setup.ini` last. Size prompt and `--yes` as for to3d.
- `tools/xrdome_depth/export.py` (new package, runs in the export venv): the export of spec 4.
- `tools/xrdome_tools/models.py`: the six generated files as entries (`used_by="depth"`, Apache-2.0, generated:
  never fetched; `models` tells you to run `setup depth`), and the source `Any_V2_S_hf` safetensors.
- Tests (stdlib, no network): the plan of steps from `--dry-run`, the pins, refusal without a GPU and with `--cpu`,
  hash mismatch handling with fake files. docs/tools.md `## setup` (depth part) and models table; CLAUDE.md status.
- Hardware check (owner, laptop): `setup depth` from scratch produces the six hashes of spec 4.

## Task 2. `xrdome-tools depth photo` (spec 4, 5)

- `tools/xrdome_tools/depth.py`: stdlib launcher subcommand `depth` (refuses without `depth/xrdome-setup.ini`,
  pointing at `setup depth`), `cli.SUBCOMMANDS` gains `depth`.
- `tools/xrdome_depth/{backend.py,photo.py,cache.py}`: ncnn Vulkan fp16 backend (fails clearly on a missing model;
  ncnn itself carries on silently), EXIF transpose, model size by displayed orientation, inference, normalisation
  and upsample, PGM writer with `.part` rename, cache key. `depth photo FILE|DIR [--force]` prints per-photo times.
- Tests: cache key, PGM header and byte order, percentile normalisation, orientation choice, all on numpy-free
  code paths where possible; the numpy/ncnn parts are tested with a fake backend in a test that skips with a
  reason when numpy is missing (CI's tools job has no numpy). docs/tools.md `## depth`.
- Hardware check (owner): 10 photos, times close to spec 2; one real camera-rotated landscape photo upright.

## Task 3. Images in 2D (spec 7, first half)

- detect: image files as `proj=flat layout=mono` with an `image` flag; player: `image-display-duration=inf`, no
  resume/seek for images; directory argument with PageDown/PageUp; filestate works per photo.
- Check and record how mpv orients EXIF-rotated JPEGs compared with an EXIF transpose (the spec's contract is the
  displayed orientation). Generate test JPEGs with each Orientation tag in the test suite (ffmpeg can write them, or
  a small fixture).
- Tests: detection units, an Xvfb smoke test with a rotated JPEG and a directory of two images. README, STATUS.
- Hardware check (owner): a portrait and a landscape photo upright and the right shape on the glasses.

## Task 4. Depth texture and stereo shader (spec 6, 7 keys)

- Load `<key>-dav2s-v1.pgm` from the cache for the open image (C reader for the spec 5 format, sha256 of the file
  for the key), R16 texture, parallax search in the flat branch, `D`, `-`/`=`, `,`/`.`, filestate for strength and
  plane; keep a C mirror of the disparity maths, unit-tested, like `xrd_flat_dir_to_uv`.
- Tests: PGM reader (good and malformed files), key computation, disparity mirror, an Xvfb smoke test with a
  synthetic step depth showing the two eyes shifted by the expected pixels. README controls, STATUS.
- Hardware check (owner): spec 6's timing limit on the Viture; by eye, default strength and plane comfortable for a
  minute, no doubled edges; record good defaults.

## Task 5. Helper service and the player as its client (spec 7)

- `depth serve`: Unix socket, JSON lines, newest-first queue with prefetch, one model loaded and kept warm.
- Player: start `xrdome-tools depth serve` (path configurable) when an image or directory opens and the socket is
  missing; request on open, prefetch next/previous, switch to 3D when the reply lands; non-blocking socket I/O in
  the main loop; helper missing or failing gives 2D and one note.
- Tests: protocol units on both sides with a fake server/client; an Xvfb smoke test with a fake helper that writes
  a synthetic depth file. docs/tools.md, README, STATUS.
- Hardware check (owner): browse 20 photos, each 3D within about 1 s; `--timing-log` while browsing < 1% missed.

## Task 6. Polish (owner picks after using Task 5)

Candidates: fade from 2D to 3D, edge-aware depth upsampling in the helper, slideshow timer, `depth photo --prepare`
for a folder ahead of time, HEIC. Held until the owner has used photo mode and chosen.

## Task 7. Video frames out (spec 8, first half)

- Player: the 322x182 downscale FBO, PBO readback one frame late, shared-memory ring, only for flat mono with 3D on.
- Helper: `video` op in `depth serve` that maps the ring and runs the 322x182 model, writing depth back with the
  frame number; a `depth bench-video` that reports achieved Hz.
- Tests: ring layout and sequence logic on both sides, readback skipped cleanly when 3D is off.
- Hardware check (owner): readback cost in `--timing-log`, helper Hz with xrdome running.

## Task 8. Video depth in the shader, smoothing (spec 8)

- Upload the newest depth into the Task 4 texture each frame it changes; temporal smoothing and scene-cut reset in
  the helper; a flicker measurement tool in the helper matching the spike's metric.
- Tests: smoothing and scene-cut units. README, docs/tools.md, STATUS.

## Task 9. Glasses run for video depth (owner)

A 30 fps and a 60 fps flat film with 3D on, a real half-SBS film to compare, a 10-minute run for thermals, and
`--timing-log` < 1% missed. Results in STATUS.
