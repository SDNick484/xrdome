# Android front end, VR180 first: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. In this repository each task is one Prompt: issue and one PR against `main` (issue-queue skill); PRs are opened, not merged.

**Goal:** Play the owner's 4320x2160 H.264 and AV1 VR180 films from a Pixel 9 Pro XL on the Viture Pro XR (then the XREAL Air 2 Pro) with head tracking, sharing the C core with the Linux player.

**Architecture:** Milestone 1 carves a `libxrdome-core` out of `src/` by listing files (no moves) in one list that meson and CMake both read. The Android app (Kotlin, `android/`) decodes with Media3 into an OES texture, copies each new frame into an RGB10_A2 texture, and draws it with the shared eye shader (rewritten to ESSL 3.00 at build time) onto a `Presentation` on the glasses. Head pose comes from new C backends that speak the glasses' USB protocols over a usbfs file descriptor handed down from `UsbManager`.

**Tech Stack:** C11, meson, cmocka, libepoxy, EGL (Linux tests); Kotlin, Android Gradle Plugin, NDK + CMake, Media3 ExoPlayer, GLES 3.0, usbfs.

**Spec:** `docs/superpowers/specs/2026-11-25-android-vr180-design.md` (section numbers below are the spec's).

## Global Constraints

- Linux behaviour and frame timing unchanged by every task (spec 2, anti-goals). The CLAUDE.md gate passes on every PR: `meson setup build -Dwerror=true && meson compile -C build && meson test -C build --print-errorlogs` and `python3 -m pytest tools/tests -q`; macOS and Windows CI jobs stay green.
- Android tasks also pass `cd android && ./gradlew assembleDebug lintDebug testDebugUnitTest` (in CI; the owner's laptop has no JDK or Android SDK, so implementers rely on the `android` workflow).
- C11 in the core; no X11, GLX, Xlib, mpv or SDL header in any file of `src/core_sources.txt`.
- No vendor SDK, AAR or header in the repository or the APK. No XRLinuxDriver source copied.
- Protocol code ported from `mgschwan/viture_virtual_display` `viture_connection.c` (MIT; its protocol came from a decompiled VITURE SDK, which `docs/licence.md` states, spec 4.1) and `badicsalex/ar-drivers-rs` (MIT) / `enricoros/android-nreal` (BSD-3-Clause) carries their notice and credit in the file header and in `docs/licence.md`.
- APK licence: GPLv3 or later as a whole (xrdome GPL-2.0-or-later + Media3 Apache-2.0), stated in `docs/licence.md` and the app's about text.
- Android: `minSdk 33`, `arm64-v8a` only, debug-signed; package `io.github.sdnick484.xrdome`.
- Glasses output: 3840x1080 SBS at 60 Hz; "late" = swap-to-swap > 20 ms (`XRD_MISSED_VSYNC_NS`).
- Device FOVs: `viture-pro` 43 deg, `xreal-air2pro` 45 deg (one table, the core's).
- Acceptance phone: Pixel 9 Pro XL. Pixel 10 Pro XL and S24 Ultra: checks only.
- Each task updates `docs/STATUS.md` (a section for the task), and user-visible Android behaviour goes in `docs/android.md` (created in Task 3).

## Review Focus

- **Glasses unplugged mid-film** (display removed and USB detached at once): playback stops, the phone shows "glasses disconnected", no crash, nothing left holding the USB device. Test in Task 6 (`PlaybackStateTest.displayRemovedStops`) and Task 7 (`test_pose_viture_usb` `read_error_goes_stale`).
- **App leaves the foreground** (Home, a call, the phone locking): player paused, Presentation dismissed, EGL and USB released; coming back returns to the picker, not a dead black screen. Test in Task 6 (`PlaybackStateTest.onStopReleases`).
- **A file that is not VR180 SBS** (16:9 flat, top-bottom, 8K, a corrupt file): a message on the phone naming why, no picture on the glasses. Test in Task 6 (`test_frame_check` cases) and Kotlin `FormatCheckTest`.
- **Glasses still in 1920x1080 mode** when play is pressed (the Viture comes back in 1080p after every reconnect, STATUS Findings): "switch the glasses to 3D (SBS)" message, not a squashed picture. Test in Task 5 (`DisplayPickerTest.rejects1080p`).
- **The pose stream stops** (USB stall, permission revoked, bad checksum burst): the view holds (tracker staleness), video keeps playing, "pose lost" shown once. Test in Task 7 (`bad_checksum_dropped`, `read_error_goes_stale`).

### Task 7: Viture Pro XR USB protocol and `viture-usb` pose backend in C (spec 5.4)

**Files:**
- Create: `src/pose/usb_io.h`, `src/pose/usbfs.{c,h}`, `src/pose/viture_proto.{c,h}`, `src/pose/pose_viture_usb.c`, `tests/test_viture_proto.c`, `tests/test_pose_viture_usb.c`
- Modify: `src/core_sources.txt`, `src/pose/pose.{c,h}`, `src/pose/pose_internal.h`, `meson.build`, `docs/licence.md`, `docs/usage.md` (the `--pose viture-usb:dev=` form), `docs/STATUS.md`

**Interfaces:**
- Produces: `usb_io.h`: `typedef struct { int (*write)(void *ctx, const uint8_t *buf, size_t len, int timeout_ms); int (*read)(void *ctx, uint8_t *buf, size_t len, int timeout_ms); void *ctx; } xrd_usb_io;` (bytes moved or -1; read returns 0 on timeout).
- Produces: `usbfs.h` (compiled for `__linux__`, which includes Android): `int xrd_usbfs_open(const char *dev_path);` (open the node, -1 with errno), `int xrd_usbfs_claim(int fd, int ifno);` (`USBDEVFS_DISCONNECT` then `USBDEVFS_CLAIMINTERFACE`; on Android the app has claimed already and this is a no-op success on `EBUSY` from the same fd), `void xrd_usbfs_release(int fd, int ifno);` (release and `USBDEVFS_CONNECT`, giving the interface back to the kernel), `int xrd_usbfs_io(int fd, uint8_t ep_in, uint8_t ep_out, xrd_usb_io *out);` using `USBDEVFS_BULK` (valid for interrupt endpoints; `ep_out` 0 for a read-only pair).
